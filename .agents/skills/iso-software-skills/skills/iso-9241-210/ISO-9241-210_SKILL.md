# ISO 9241-210:2010 - Human-centred Design for Interactive Systems

## Scope
Provides overview of human-centred design (HCD) activities for interactive systems (software, hardware, services, websites, consumer products). Replaces ISO 13407:1999. Covers planning, managing, and executing HCD processes; does not detail specific methods/techniques.

## Key Terms
- **Human-centred design (HCD)**: Approach focusing on users, tasks, environments using ergonomics/usability knowledge to make systems usable/useful.
- **Context of use**: Users, tasks, equipment (hardware/software), physical/social environments.
- **Usability**: Effectiveness, efficiency, satisfaction in specified context of use.
- **User experience**: User perceptions/responses from system use.
- **Stakeholder**: Individual/organization with interest in system characteristics.
- **Interactive system**: Combination of hardware/software/services receiving user input and providing output.

## Principles of Human-Centred Design
1. **Based on explicit understanding of users, tasks, environments** (Clause 4.2)
2. **Users involved throughout design and development** (Clause 4.3)
3. **Design driven and refined by user-centred evaluation** (Clause 4.4)
4. **Process is iterative** (Clause 4.5)
5. **Design addresses whole user experience** (Clause 4.6)
6. **Design team includes multidisciplinary skills/perspectives** (Clause 4.7)

## HCD Activities (Clause 6)
### 1. Understand and specify context of use (6.2)
- Identify all user/stakeholder groups and their goals/constraints
- Document user characteristics (knowledge, skills, capabilities, preferences)
- Define user goals/tasks (frequency, duration, interdependencies, health/safety risks)
- Describe technical, physical, social, cultural environments
- Produce **context-of-use description** (working document updated throughout project)

### 2. Specify user requirements (6.3)
- Derive requirements from user needs + context of use
- Include: intended context of use, ergonomics/UI knowledge, usability objectives (measurable criteria), organizational requirements
- Resolve trade-offs between conflicting requirements; document rationales
- **User requirements specification** must be: testable, verified by stakeholders, internally consistent, updated as needed

### 3. Produce design solutions (6.4)
- Design user tasks, user-system interaction, user interface to meet requirements
- Apply design principles (from ISO 9241-110): suitability for task, self-descriptiveness, conformity with user expectations, suitability for learning, controllability, error tolerance, suitability for individualization
- Use scenarios, simulations, prototypes/mock-ups to make solutions concrete
- Iterate based on user-centred evaluation feedback
- Communicate design solutions to implementation teams with justifications/trade-offs

### 4. Evaluate design against requirements (6.5)
- **User-centred evaluation** (required): Evaluate from user perspective
  - **User-based testing**: Users perform tasks with prototypes/products in realistic contexts; collect performance/satisfaction data
  - **Inspection-based evaluation**: Experts assess against guidelines/requirements/checklists
  - **Long-term monitoring**: Collect field data post-deployment (help-desk, logs, satisfaction surveys)
- Allocate resources for early feedback + final validation
- Use results to refine requirements/design iteratively

## Planning HCD (Clause 5)
- **Responsibility**: Consider usability importance, risk levels, development environment
- **Content of plan**: Identify methods/resources, integration procedures, responsible parties, feedback mechanisms, milestones, timescales
- **Integration**: HCD plan forms part of overall project plan with same disciplines (responsibilities, change control)
- **Timing/resources**: Allocate time for iteration, user feedback, evaluation; start HCD at earliest project stage

## Conformance (Clause 8)
Achieved by:
1. Satisfying all requirements
2. Identifying applicable recommendations
3. Explaining why recommendations are not applicable
4. Stating whether applicable recommendations have been followed

Use Annex B checklist to assess applicability/conformance.

## HCD Outputs (Table 1)
| Activity | Output |
|----------|--------|
| Understand context of use | Context of use description |
| Specify user requirements | Context of use specification, User needs description, User requirements specification |
| Produce design solutions | User interaction specification, User interface specification, Implemented user interface |
| Evaluate design | Evaluation results, Conformance test results, Long-term monitoring results |

## When to Use
- Managing interactive system development projects
- Implementing human-centred design processes
- Auditing design processes for HCD compliance
- Training teams on HCD principles
- Aligning with ISO 13407:1999 migration
- Integrating usability/accessibility into system life cycle

## Relationship to Other Standards
- Replaces **ISO 13407:1999**
- Builds on **ISO 9241-11** (Usability definition, context of use)
- References **ISO 6385** (Ergonomic principles for work systems)
- Part of **ISO 9241** Ergonomics of human-system interaction series
- Guidance on methods: **ISO/TR 16982** (Usability methods), **ISO/TR 18529** (HCD process models)
- Dependability: **IEC 62508** (Human aspects of dependability)

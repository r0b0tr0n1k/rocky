# Manage Environment Variables

Rocky runs in **two worlds** with two different env-loading models:

1. **Dev on this PC** — `pnpm dev` (Turborepo) runs the api / web / mob / docs workspaces, each reading its **own** `.env` file.
2. **Docker (compose)** — `docker compose up` auto-loads the **root** `.env` and injects vars into containers; the API receives `DATABASE_URL` **verbatim** and derives its internal db config from it.

The single rule that governs both: **every secret lives only in a local `.env`, never in git.** `.env.example` files are the template; `.env` files are the filled-in secret-bearing copies and are git-ignored.

---

## The two loading models (grounded)

### Dev on this PC

Each workspace loads env independently — there is **no single root `.env`** that feeds dev:

| Workspace | How it loads `.env` | File it reads |
| --- | --- | --- |
| `apps/api` | `scripts/dev.mjs` runs `import "dotenv/config"` (dotenv), then `tsx --import dotenv/config` for `main.ts` | `apps/api/.env` |
| `apps/web` | Next.js auto-loads `.env` from the app dir | `apps/web/.env` |
| `apps/mob` | Expo auto-loads `.env`; only `EXPO_PUBLIC_*` are inlined (at **build** time) | `apps/mob/.env` |
| `packages/database` | `seed.ts` / Drizzle Kit via `dotenv/config` | `packages/database/.env` |

`turbo.json` additionally declares a `globalPassThroughEnv` list (`PG_PORT`, `PG_HOST`, `PG_USER`, `PG_PASS`, `PG_DB`, `API_PORT`, `WEB_PORT`, `DOCS_PORT`, `LANDING_PORT`, `API_URL`, `WEB_URL`, `LANDING_URL`). Those vars, **if present in your shell environment**, are forwarded to every task. Use them for worktree/port overrides (see below) — they are not required for a normal single-machine dev.

> `apps/api/src/config.ts` reads `DATABASE_URL` (and derives its internal db config from it), plus `ENVIRONMENT`, `VERSION`, `NODE_ENV`, `BETTER_AUTH_SECRET`, `PORT`/`API_PORT`, `BASE_SERVICE_URL`, `CORS_ORIGINS`, `TRUSTED_ORIGINS`, `REQUEST_LOGGING` (plus the PDF-signer and credential-key vars). All of these come from `apps/api/.env` in dev.

### Docker (compose)

`docker-compose.yml` is launched from the repo root and **auto-loads `./.env`** for `${VAR}` interpolation. The api service receives the connection string **verbatim** — compose passes `DATABASE_URL=${DATABASE_URL}` straight through; it does **not** assemble it from `DB_HOST`/`DB_PORT`/`PG_*`. `apps/api/src/config.ts` then **derives** its internal `appConfig.db` (`host`/`user`/`password`/`name`/`port`) by parsing `DATABASE_URL` with `new URL(...)`.

So in compose you set a **single** `DATABASE_URL` in the root `.env` (or injected into the environment) — there are no `DB_HOST`/`DB_PORT`/`DB_USER`/`PG_*` vars:

```
# Bundled db service (starts by default — profiles are off):
DATABASE_URL=postgres://tbot:<POSTGRES_PASSWORD>@db:5432/tbot
# External DB (separate host/VM):
DATABASE_URL=postgres://tbot:<pw>@<host>:5432/tbot
```

> **Write the password literally.** Compose does not expand `${VAR}` inside a `.env` *value*, so `DATABASE_URL=...${POSTGRES_PASSWORD}...` reaches the container unexpanded and breaks the connection. The `POSTGRES_PASSWORD` var is only used to initialize the bundled `db` container and must equal the password embedded in `DATABASE_URL`.

The `db` service runs by default (its `profiles: [local-db]` is commented out); `web` depends on `api` being `service_healthy`, and both api/web healthchecks TCP-probe their own service name (`nc -z api 8080`, `nc -z web 3000`) inside the compose network — no localhost/port-number coupling. The `web` image takes `NEXT_PUBLIC_API_URL` as a **build arg** (`docker-compose.yml` passes `--build-arg`), so it is frozen at image-build time. Everything else in `api`/`web` is a **runtime** env var injected by compose.

## The canonical file set

| File | Purpose | Consumed by |
| --- | --- | --- |
| `.env` (root) | Compose secrets — single `DATABASE_URL` (+ `POSTGRES_PASSWORD` for the bundled db) + auth/domain vars | `docker compose`, `scripts/setup-tunnel.sh` |
| `.env.example` (root) | Template for the above | — (copy target) |
| `apps/api/.env` | API runtime config (DB, auth, ports, signer, creds) | `apps/api` dev |
| `apps/web/.env` | `API_URL`, `BETTER_AUTH_SECRET`, `NEXT_PUBLIC_*` | `apps/web` dev |
| `apps/mob/.env` | `EXPO_PUBLIC_API_URL`, Cloudflare Access service token | `apps/mob` dev/build |
| `packages/database/.env` | `DATABASE_URL` (Drizzle Kit + seed) | `packages/database` |

## Quick start — dev on this PC

```bash
# 1. API: copy the template, fill secrets
cp apps/api/.env.example apps/api/.env
#    set at minimum: ENVIRONMENT=dev, BETTER_AUTH_SECRET, DATABASE_URL

# 2. Web admin
cp apps/web/.env.example apps/web/.env

# 3. Mobile
cp apps/mob/.env.example apps/mob/.env

# 4. Database (no .example ships — create it)
#    packages/database/.env  ->  DATABASE_URL=postgres://tbot:<pw>@192.168.1.109:5432/tbot

# 5. Run everything
pnpm dev
```

Mandatory gotcha: `apps/api/src/config.ts` validates `ENVIRONMENT` against a zod enum (`dev|production|test|staging`) with **no default** — the API refuses to start unless `apps/api/.env` sets `ENVIRONMENT=dev`.

Keep the dev DB host consistent: `packages/database/.env` `DATABASE_URL` and `apps/api/.env` `DATABASE_URL` must point at the **same** Postgres (the LAN box `192.168.1.109:5432/tbot` in this setup).

## Quick start — Docker (compose)

```bash
# 1. Root compose secrets
cp .env.example .env
#    MANDATORY for a VM deploy: ROCKY_DOMAIN, DATABASE_URL, POSTGRES_PASSWORD,
#    BETTER_AUTH_SECRET, TUNNEL_TOKEN
#    Everything else derives from ROCKY_DOMAIN — leave it alone unless you must override.

# 2. Bundled Postgres starts by default (its `profiles` are commented out).
#    For an external DB, point DATABASE_URL at it; this step is then optional.

# 3. Full stack (api + web + docs)
docker compose up -d

# 4. Optional Drizzle Studio (dev profile)
docker compose --profile dev up drizzle-studio
```

The Cloudflare Tunnel token is generated into `.env` by the bootstrap script. It requires `CLOUDFLARE_API_TOKEN` **and** `CLOUDFLARE_ACCOUNT_ID` in the environment, and reads `ROCKY_DOMAIN` from `.env`:

```bash
CLOUDFLARE_API_TOKEN=<api-token> CLOUDFLARE_ACCOUNT_ID=<acct-id> \
  ROCKY_DOMAIN=techno.party \
  bash scripts/setup-tunnel.sh
```

## Secrets hygiene

| Secret | Where it lives | Generate with |
| --- | --- | --- |
| `POSTGRES_PASSWORD` | root `.env` (compose) / `DATABASE_URL` (dev) | random string |
| `BETTER_AUTH_SECRET` | root `.env` + `apps/api/.env` + `apps/web/.env` | `openssl rand -base64 32` |
| `TUNNEL_TOKEN` | root `.env` | `scripts/setup-tunnel.sh` |
| `DRIZZLE_MASTER_PASS` | root `.env` | random string |
| `NEXT_PUBLIC_MAPTILER_API_KEY` | `apps/web/.env` | MapTiler dashboard |
| `MAPTILER_API_KEY` | api container (Docker) — bridged from `NEXT_PUBLIC_MAPTILER_API_KEY` in compose | same MapTiler key as above (see [troubleshooting](#troubleshooting)) |
| `EXPO_PUBLIC_CF_ACCESS_CLIENT_SECRET` | `apps/mob/.env` | Cloudflare Zero Trust |
| PDF signer (`ROCKY_P12_PATH` / `ROCKY_HSM_*`) | `apps/api/.env` | see [Sign PDF documents](/runbooks/sign-pdf-documents) |
| Credential key (`ROCKY_CRED_KEY` / `ROCKY_CRED_KEY_PATH`) | `apps/api/.env` | Ed25519 keypair |

**Git safety:** root `.gitignore` ignores `.env`; `apps/web/.gitignore` ignores `.env*`; `apps/mob/.gitignore` ignores `.env*.local`. Verify before committing:

```bash
git status --ignored -- '.env' 'apps/**/.env*'
# no .env should ever appear in `git status` as tracked
```

Never paste a real secret into an `.env.example` or into a doc/ADR.

## Worktree / port isolation (parallel dev)

`turbo.json` passes `API_PORT` / `WEB_PORT` / `DOCS_PORT` / `LANDING_PORT` through to tasks. To run a second worktree on different ports, export them in your shell (or source a `.env.worktree`):

```bash
export API_PORT=8081 WEB_PORT=4001
pnpm dev
```

`apps/api/.env.example` references a `scripts/with-worktree-env.sh` helper that is meant to source `.env.worktree` for you — that script is currently an **empty stub**. Until it is implemented, export the ports yourself as shown above.

## Build-time vs runtime (Docker)

- **Build-time (frozen in the image):** `apps/web` `NEXT_PUBLIC_API_URL` (compose `--build-arg`). Change it → **rebuild** the web image (`docker compose build web`).
- **Runtime (hot via compose env):** `api` `DATABASE_URL`, `BETTER_AUTH_*`, `CORS_ORIGINS`, `AUTH_*`, `MAPTILER_API_KEY`, `web` `API_URL` / `BETTER_AUTH_SECRET`. Change → `docker compose up -d` (no rebuild).
- **Mobile has no Dockerfile.** Expo builds are native; `EXPO_PUBLIC_*` are baked at `expo` build time and cannot be overridden by a `.env.worktree` afterward.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| API exits immediately in dev | `ENVIRONMENT` unset (zod enum, no default) | Set `ENVIRONMENT=dev` in `apps/api/.env` |
| Dev connects to wrong DB | `packages/database/.env` `DATABASE_URL` ≠ `apps/api/.env` `DATABASE_URL` | Point both at the same host |
| Compose API can't reach DB | `DATABASE_URL` missing/wrong in root `.env`, or password ≠ `POSTGRES_PASSWORD` (bundled db) | Set a single correct `DATABASE_URL` in root `.env`; ensure its password matches `POSTGRES_PASSWORD` |
| Web shows stale API URL in Docker | `NEXT_PUBLIC_API_URL` is build-time | `docker compose build web` then `up -d` |
| Mobile hits wrong API after IP change | `EXPO_PUBLIC_*` baked at build | Edit `apps/mob/.env`, restart Expo |
| Cookie/session not shared web↔api | `AUTH_COOKIE_DOMAIN` / `AUTH_BASE_URL` / `CORS_ORIGINS` inconsistent | Align across `api` + `web` (derive from `ROCKY_DOMAIN`) |
| `git status` shows a `.env` | File not ignored / wrong name | Ensure it's named exactly `.env` (root), `.env*` (web), `.env*.local` (mob) |
| api exits at boot: `GEO_MAP_PROVIDER_UNCONFIGURED` | `MAPTILER_API_KEY` unset in the api container (`@rocky/geo` `MapTilerMapService`) | Compose already bridges `MAPTILER_API_KEY=${NEXT_PUBLIC_MAPTILER_API_KEY}`; or set `MAPTILER_API_KEY` explicitly in root `.env` |

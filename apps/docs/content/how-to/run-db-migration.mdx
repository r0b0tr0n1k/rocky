# Run a DB migration (db-recreate.sh)

Apply Drizzle schema + RLS to the dev DB (`192.168.1.109:5432/tbot`).

## When
Schema changed (new table, RLS policy, enum). Use `./scripts/db-recreate.sh` for a clean state, or `cd packages/database && pnpm generate` + `node ../../scripts/fix-rls-sql.mjs` for an iterative apply.

## The two gotchas (learned)
- **`check_function_bodies = off`** — `farm_org_id(p_farm_id)` references `farms` defined *later* in the file; default `on` rejects compile. The script prepends `SET check_function_bodies = off;` so the function compiles and validates at first RLS call.
- **RLS `$N` placeholders** — `drizzle-kit` emits `$1`/`$2` and leaves `${...}` templates unresolved. `fix-rls-sql.mjs` rewrites them to literals (`ARRAY[...]`). Source tables should emit literal `ARRAY[...]` via `sql.raw` to skip the post-process entirely.

## Steps
1. Edit the Drizzle schema in `packages/database/src/schema/*`.
2. `./scripts/db-recreate.sh` (wipes + regenerates + seeds).
3. Verify: `SELECT count(*) FROM pg_policies;` and `SELECT to_regclass('sm.device_tokens');`.

> This runbook is real — the `device_tokens` + 49-policy rebuild used exactly this.

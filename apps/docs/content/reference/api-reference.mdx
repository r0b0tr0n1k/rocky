The Rocky API is a **tRPC** layer generated from NestJS routers (`@Router` / `@Query` / `@Mutation`) by `nestjs-trpc generate` into `packages/trpc/src/generated/server.ts`. It currently exposes **25 routers / 183 procedures**. The NoDrift ideology holds at the boundary: the client `AppRouter` type *is* the contract, so drift is impossible by construction (enforced by `check:trpc-boundary` in `ci:checks`).

## Where the surface lives

- **`packages/trpc/src/generated/server.ts`** — the generated `AppRouter` type. Web and mobile consume it for end-to-end type safety. Regenerate with `pnpm generate:trpc`.
- **`@rocky/validators`** — every procedure’s input/output Zod schema (the "Diamond Seal" API contracts). Drift is caught by the NoDrift guillotine.
- **Domain services** — the business logic behind each procedure (see per-domain ADRs).

## Why not Nextra’s `TSDoc`?

Nextra’s `<TSDoc>` component turns TS types into property / parameter / return tables. It is **intentionally not used here**: under Next 16 + Turbopack it fails to resolve the `next-mdx-import-source-file` virtual module that `<TSDoc>` pulls in at build time (the same rot that broke `pnpm build`). Instead this page is generated **deterministically** from the router source — no Turbopack virtual modules, no dependence on Nextra’s broken component. Tracked in **ADR-0052**.

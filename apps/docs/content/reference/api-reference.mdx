# API Reference

The Rocky API surface is a **tRPC** layer generated from NestJS routers
(`@Router` / `@Query` / `@Mutation`) by `nestjs-trpc generate` into
`packages/trpc/src/generated/server.ts`. As of the current generation it exposes
**24 routers / 156 procedures**. The NoDrift ideology holds at the boundary:
the client `AppRouter` type *is* the contract, so drift is impossible by construction
— enforced by `check:trpc-boundary` in `ci:checks`.

## Where the surface lives

- **`packages/trpc/src/generated/server.ts`** — the generated `AppRouter`
  type. Web (`apps/web`) and mobile (`apps/mob`) consume it for end-to-end
  type safety. Regenerate with `pnpm generate:trpc`.
- **`@rocky/validators`** — every procedure's input/output Zod schema
  (the "Diamond Seal" API contracts). Drift between a schema and its Dumb
  Zod source is caught by the NoDrift guillotine.
- **Domain services** — the business logic behind each procedure (see the
  per-domain ADRs, e.g. ADR-0026 health, ADR-0024 ear-tag).

## TSDoc (deferred)

Nextra's `<TSDoc>` component turns TypeScript types into property /
parameter / return tables. It is **not yet wired** in this docs app: it
requires the docs build to resolve `@rocky/*` workspace imports *and* a
Turbopack-compatible `tsdoc` loader. Nextra 4.6.1 + Next 16 / Turbopack
currently fails to resolve the `next-mdx-import-source-file` virtual module
that `<TSDoc>` pulls in at build time. See ADR-0052 (Documentation
Architecture) for the tracked follow-up. Until then, treat
`packages/trpc/src/generated/server.ts` + the validators as the
authoritative, machine-checked reference.

## What belongs here (when wired)

- `AppRouter` — the full tRPC surface (procedures + routers).
- `@rocky/validators` API Zod schemas.
- Domain service method signatures.
